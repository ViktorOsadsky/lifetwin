# Motion / useful UX research checkpoint

2026-10-23. Paused at root's request to release an agent slot. This is a source-backed checkpoint, **not a completed rendered-interaction study**. No skill or site files changed. Browser viewport was not changed.

Evidence: **D** official documentation/case description; **DOM** observed live semantic page; **I** recommendation inferred from that evidence. Product mobile/reduced-motion behavior has not been tested here. No purchase, signup, or external content submission occurred.

## Eight useful source clusters

1. **[Apple MacBook Pro product narrative](https://www.apple.com/macbook-pro/) — D/DOM.** Live browser exposes separate Buy/Compare/Specs navigation; a current-device selector updates an upgrade-comparison area; highlights use named tabs and an explicit Play button; product animations have useful image descriptions. **Task:** understand a product and compare the relevant model. **Trigger/response:** selection and tab controls have explicit semantic endpoints, rather than relying solely on scroll. **Interruption/mobile/reduced:** controls were observed, not activated; exact motion and responsive behavior remain untested. **I:** keep the product/task destination available throughout a narrative; direct controls and meaningful final content should survive skipped animation. A long scroll story does not replace comparison or selection.

2. **[Linear — creating issues / drafts](https://linear.app/docs/creating-issues) — D.** An issue can be opened through `C` or the visible create action. Navigating away temporarily preserves the editor locally; Escape/close offers saving a persistent draft. Inline title/description edits and description history support correction. **Task:** capture work without losing context. **Trigger/response:** create → editor; interruption → draft policy; return → prior content. **Mobile/reduced:** not observed; do not infer desktop shortcuts are the mobile solution. **I:** interruption is a domain-state contract, not just the direction an overlay animates. Choose what happens to unsaved work before choosing the close transition.

3. **[Shopify — product variants](https://shopify.dev/docs/storefronts/themes/product-merchandising/variants) — D.** Shopify recommends separate option controls and requires product media and price to reflect the selected variant; deep links must resolve the selected variant. **Task:** configure the exact item being considered. **Trigger/response:** change option → corresponding selection, media, price. **Interruption:** inspect rapid option changes for stale media/price; this race-handling recommendation is I, not a demonstrated store behavior. **Mobile/reduced:** not observed. **I:** animate the transition only after one authoritative selection updates the useful facts; never let a decorative product scene disagree with the actual chosen variant.

4. **[Stripe Checkout](https://stripe.com/payments/checkout) — D.** Official feature descriptions identify responsive layouts, real-time card feedback, potentially misspelled email-domain feedback, descriptive localized errors, and adjustable quantities. **Task:** complete an accurate form with less correction work. **Trigger/response:** input/quantity change → specific local feedback. **Interruption/mobile/reduced:** responsiveness is a vendor claim; no form/payment was tested. **I:** usefulness comes from response accuracy and placement, not the amount of movement. Keep the field, error, and corrective action near one another; avoid explanatory paragraphs when a precise field-level message suffices.

5. **[Locomotive — Lightship case](https://locomotive.ca/en/work/lightship-1), 2025 — D.** The studio explicitly describes replacing its prior scroll-heavy presentation with structured product-first layers and contextual interactive 3D. **Task:** understand an unfamiliar vehicle and its systems. **Trigger/response:** navigable layers and contextual system visualization are described, not personally tested. **Interruption/mobile/reduced:** not observed. **I:** a studio reference can justify *reducing* scroll choreography. Pin a scene only while its changing view explains something; leave users a navigable direct path to product information.

6. **[GSAP ScrollTrigger](https://gsap.com/docs/v3/Plugins/ScrollTrigger/) + [gsap.matchMedia](https://gsap.com/docs/v3/GSAP/gsap.matchMedia()/) — D.** `scrub:true` follows progress directly; numeric scrub adds catch-up time. Snap is canceled by new scroll interaction. `gsap.matchMedia()` collects and reverts created animations/ScrollTriggers when conditions change; it supports breakpoint and motion-preference conditions. **I:** test reverse and rapid scroll, not just forward playback. Make the motion score distinguish trigger-once, progress-linked, and input-driven behaviors. Use media conditions to choose a meaningful mobile/reduced variant rather than merely shortening all durations. API examples do not establish good pacing or justify mandatory snapping.

7. **[Chrome — scroll-driven animations](https://developer.chrome.com/docs/css-ui/scroll-driven-animations), original published 2023, current page checked today — D.** Scroll timelines follow scroll position; view timelines follow a subject through the scrollport. `animation-range` defines the useful interval; untransformed layout boxes determine ranges. **I:** choose native timeline primitives for simple progress-linked DOM effects when supported; use a readable base state plus feature detection. A web article retaining historical version/flag notes is not evidence of current universal support. Check the actual browser support needed by the project rather than copying an old polyfill or experimental flag instruction.

8. **W3C WAI: [target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [dragging](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html), [interaction animation](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html) — D.** AA target-size minimum is 24 CSS pixels or specified exceptions/spacing, not a universal 44px compliance rule. Keyboard equivalence alone does not supply a tap/click alternative to dragging. Interaction-triggered nonessential motion can be disabled under AAA 2.3.3; normal user-controlled scrolling is distinguished from added parallax. **I:** use comfortable touch targets as a design choice, but report standards accurately. Reduced motion must preserve content/task access, not freeze a scrubbed scene halfway or leave reveal text hidden.

## Immediate decision rules

- Write the real action's state contract before its animation: selected value, visible consequence, undo/correction, unsaved work, and outcome.
- Give each scroll sequence an information endpoint. If the same idea is already clear, more scroll travel and captions are not added value.
- Keep essential controls useful during interrupted motion; rapid taps/reverse scroll must not queue stale UI results.
- Mobile is a different reading/manipulation distance: keep the changed object/result beside the control and replace gesture-only manipulation with tap paths.
- Use precise local labels and feedback; remove captions that describe the implementation or repeat visible behavior.
- Separate observation, vendor claims, and inference. Product reputation and documented APIs do not prove a rendered mobile/reduced-motion pass.
