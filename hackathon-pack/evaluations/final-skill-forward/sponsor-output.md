**Recommendation: Cartesia primary; Convex for the durable backend, with Convex prize entry conditional on its unpublished rubric.** Build a voice receptionist for a community repair shop: a caller asks for a repair appointment, corrects the preferred day while the agent is talking, hears two available slots, explicitly confirms one, and sees exactly one saved booking survive refresh. Use fictional customers and a seeded shop schedule. Voice is the input, clarification and confirmation channel rather than a spoken dashboard. A visible text transcript, slot list and Confirm/Cancel buttons provide another way through the same task.

## Bounded integration design

Read `listSlots(shopId, localDate, timezone)` from Convex; transform the caller's preference into two explicit dated/timezoned choices; save a confirmed booking transactionally. Use one Cartesia Managed Agent, one hosted LLM from its catalogue and one HTTPS adapter. No separate LLM key is needed for the selected managed route. Current official docs confirm managed conversation and webhook tools, including configurable server authentication and timeouts; implementation must inspect the installed SDK/generated API before writing calls.

Proposed adapter operations are our application contract, not claimed provider methods: `listSlots`, `prepareBooking`, `confirmBooking`, `getBookingStatus`. The agent may propose; the backend issues a short-lived proposal ID bound to session/shop/slot/revision. A spoken or tapped confirmation must refer to the current proposal. `confirmBooking` checks authorization, proposal expiry/revision and availability inside one Convex mutation, stores a stable action ID, and returns the same booking for repeated action IDs. Backend derives scope from authenticated session context; model-supplied shop/user IDs cannot grant authority. Changing the requested day revokes the previous proposal. Barge-in stops speech but does not automatically cancel an already committed booking: query canonical status and explain the outcome before offering an explicit cancellation.

Cartesia's current webhook schema nests outbound method/url/body/auth under `api_schema`; use a saved server secret and a bounded timeout. Do not expose a broad backend credential or accept unauthenticated booking requests. Current client auth docs specify server-created short-lived browser access tokens and an Agents grant. Keep the Cartesia API key server-side. Exact live schema/SDK compatibility is unverified here. Convex mutations are transactional and deterministic; third-party calls belong in actions, not a mutation. Do not place voice/network calls inside the booking transaction.

Scope: one shop, one appointment type, two days of fictional slots, create/cancel, visible current booking and manual recovery. The prototype's Convex booking is its actual saved output; Google/Outlook calendar, telephone carrier, SMS and email delivery are **simulated/not connected** and must be labelled that way. No payments or medical appointments. Do not claim that a saved internal booking reached an external calendar.

## Build and prove in less than 36 hours

| Elapsed budget | Concrete result and stop rule |
|---|---|
| 0–2 h | Verify official permitted start, team/check-in eligibility, existing Cartesia/Convex access, installed SDK versions and quotas. Get one read and one authenticated webhook round trip on fictional data. If access blocks the core, remove the prize claim early. |
| 2–8 h | Durable schema and transactional confirmation, idempotency, slot collision and refresh proof. Build the visible text flow before voice wiring. |
| 8–15 h | Managed agent + tools, text captions/mic state, the same confirmation/cancel path. Keep call/session IDs and sanitized tool results. |
| 15–23 h | Run the failure cases below and correct failures. No provider additions. |
| 23–29 h | Rehearse a complete live voice flow and record a two-minute backup. Prepare screenshot, repository access, README, known limits and sponsor contribution proof. |
| 29–33 h | Buffer for real device/microphone failures, source recheck, judge access and submission preparation. Freeze scope. Target submission by **8:15 AM event-local Sunday**, or earlier if this conflicts with the confirmed official cutoff. |

Planned hard tests: interrupt at slot reading; change date before confirm; repeat confirmation/tool delivery; two sessions contend for one slot; refresh after commit; dropped response after commit; expired proposal; malicious customer notes trying to override booking scope; microphone denial; provider timeout; unavailable slot; wrong timezone. Expected result is one canonical booking or a clear uncommitted state, never a guessed success. Retrying a timed-out confirmation first queries its action ID. Text fallback remains usable; a fallback is not proof of live voice use.
