# Creative web worlds and mobile play

Make the experience visually specific, clear to operate and satisfying in motion. Judge the rendered work and its interactions. Novelty, working code, reference counts and confident scores do not establish excellent design.

## Set the direction and fidelity

Identify the subject, audience, useful action and desired visual character. Preserve the user's chosen direction. For an open brief, choose a concrete subject and compare genuinely different compositions with real content, actual type and a production centerpiece. Explain the decisive choice briefly; do not stall an authorized experiment for optional preferences.

Match fidelity to the request. For visual prototypes, use lightweight state and representative content to demonstrate selection, manipulation, transitions and feedback. Do not build authentication, payment, audio-generation or export pipelines merely to prove that a visual design works. When a real product integration is requested, verify its actual outcome and limits. A skill-refinement experiment needs the smallest representative slice that reveals a decision failure, not another complete website.

For Flutter mobile work, read [flutter-mobile.md](references/flutter-mobile.md). ## Study relationships, then produce the material

For open web composition briefs compare [visual-grammars.md](references/visual-grammars.md). For web research use [source-atlas.md](references/source-atlas.md) and [production-lessons.md](references/production-lessons.md); for mobile/game work use its routed atlas. Inspect relevant current rendered examples when possible. Study a precise relationship: image/type scale, composition, material/light, scroll pacing or a control's response. Separate observed behavior, first-party claims and your interpretation. Reputation and thumbnails are insufficient comparisons.

Produce the asset, typography and composition before decorating them. Choose authored illustration, licensed photography, generated imagery, custom geometry or an intentional type composition. Inspect silhouette, detail, crop, edges and light at actual display size. Improve a weak centerpiece instead of hiding it behind motion. Use suitable actual fonts and optical line breaks, tracking, width, weight and spacing. A large default heading is not typographic authorship.

Compose distinct section roles and a coherent grammar for controls, marks, surfaces and image treatment. Avoid repeating one giant-wordmark/slogan rhythm across different briefs. Empty space, asymmetry and overlap should establish hierarchy. Do not fabricate prestigious clients, reviews or performance claims as ornament.

## Make interactions feel direct

Keep the manipulated object, visible result and controls together. Selection should agree across scene and UI. Commit input promptly; let animation follow that state and yield to the next action. Preserve position, focus and draft ownership when context changes. Give hover, focus, press, loading, empty and error states enough visual distinction to explain what happened.

Keep words that name actions, identify content, distinguish state or explain recovery. Remove ambient captions, redundant invitations, implementation labels and text narrating obvious effects. Sparse UI still needs understandable controls and useful errors. For substantial workflows, [interaction-contracts.md](references/interaction-contracts.md) covers state, correction and persistence; apply its real-output checks only at the requested fidelity.

## Choreograph native scroll and mobile together

For animated web work read [motion-and-mobile.md](references/motion-and-mobile.md); Flutter motion mechanics live in its routed reference. Score each important sequence as intent → trigger/interval → changing subject → endpoint → interruption/reversal → mobile/reduced variant. Choose progress-linked, triggered or input-driven behavior deliberately. Prefer a finite, authored sequence connecting meaningful views to identical fade-ups on every section. Keep native scrolling and direct access to useful content; pin only while the changing view earns its travel.

Compose mobile as a primary experience. Reconsider image crop, type, navigation, touch reach and control/result placement. Replace excessive desktop pinning or gesture-only manipulation with shorter flowing/sticky views and tap alternatives. Keep forms usable with the keyboard and respect safe areas and zoom. Do not shrink the desktop composition and leave its scroll distance unchanged.

Reduced motion retains complete resolved content and working state. Feature-detect progressive effects, respond to preference/breakpoint changes and clean up owned timelines. Test reverse and interrupted input. Explicitly judge the intermediate mobile composition: subject scale/crop, collisions with type, empty travel and the next useful view. A sequence with good endpoints can still fail here. Recompose or simplify the route; do not merely change easing. Essential content must remain available.

## Choose the medium deliberately

For web deliverables, use HTML/CSS/SVG for precise editorial or graphic work. Use actual Three.js/R3F when shape, camera, material/light or spatial manipulation belongs to the design; [real-3d-recipe.md](references/real-3d-recipe.md) covers production and shared state. CSS depth is 2.5D, not real 3D. Do not silently substitute 2D when real 3D is requested. Keep essential controls semantic and provide usable fallbacks. Verify external APIs when using them; measure performance before claiming it.

## Review, correct, test the instruction

Use the shared still/interaction principles in [craft-review.md](references/craft-review.md), applying its web-specific scroll and DOM checks to web work only. Flutter uses its routed runtime and phone checks. First inspect the still composition; then observe initial, intermediate, settled and reversed/interrupted motion. For web work test an equivalent meaningful interaction on desktop and narrow mobile; for native work test the target phone constraints and input states. For exact mobile reference relationships use [mobile-comparison-gates.md](references/mobile-comparison-gates.md). Compare specific moments against appropriate industry references at comparable sizes: hierarchy, material, pace, feedback distance, reading density and recovery. State the actual gap rather than inventing a quality score.

Revise the highest-impact observed weakness and render again. If the direction stalls, change the production approach rather than accumulating effects or captions. For substantial skill evaluation, use the [fresh-context build and critique protocol](references/forward-testing.md) when delegation is available and authorized. Inspect the actual output, identify which instruction caused or failed to prevent the problem, and make a narrow reusable correction. Different subjects alone do not prove stylistic range.

Deliver the requested artifact and concise evidence of the refinement. Distinguish visual judgment, interaction observations and untested claims. Never declare a masterpiece because checks pass.
